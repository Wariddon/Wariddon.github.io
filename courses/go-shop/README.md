# คอร์ส Go ผ่านโปรเจกต์ร้านค้า

ใช้ Go 1.24 ขึ้นไป และ Node.js 24 สำหรับบทเว็บ เปิด PowerShell แล้วเริ่มจากโฟลเดอร์ courses/go-shop ภายใน repo

```powershell
git clone https://github.com/Wariddon/Wariddon.github.io.git
cd Wariddon.github.io/courses/go-shop
go version
```

ถ้ามี repo อยู่แล้ว เปิด PowerShell ใน courses/go-shop ได้เลย บท 7, 8 และ 10 เขียนไฟล์ฝึกลงในโฟลเดอร์ปัจจุบัน

## บทที่ 1 · โปรแกรมแรกและตัวแปร

เริ่มที่ฟังก์ชัน main ภายใน package main เครื่องหมาย := สร้างตัวแปรแล้วให้ Go อนุมานชนิดจากค่าด้านขวา ใช้ string เก็บชื่อ และ int เก็บจำนวนเงินบาทเต็ม พิมพ์ด้วย fmt.Printf โดย %s รับข้อความ ส่วน %d รับจำนวนเต็ม

```powershell
go run ./01-first
```

[01-first/main.go](01-first/main.go)

**ลองทำ** ลองเพิ่มค่าจัดส่งคงที่ 40 บาท แล้วเปลี่ยนจำนวนเสื้อเป็น 3 ตัว

**ตรวจคำตอบ** ก่อนแก้ได้ 500 บาท หลังเพิ่มค่าส่งและเปลี่ยนจำนวนได้ 790 บาท

## บทที่ 2 · ตัดสินใจด้วย if

ตั้งค่าเริ่มต้นให้ค่าส่งก่อน แล้วให้ if เปลี่ยนค่าเมื่อเข้าเงื่อนไข := สร้างตัวแปร ส่วน = เปลี่ยนค่าที่มีอยู่ >= รวมยอดที่เท่ากับเกณฑ์ด้วย

```powershell
go run ./02-conditions
```

[02-conditions/main.go](02-conditions/main.go)

**ลองทำ** เปลี่ยนค่าส่งเป็น 50 และเกณฑ์ส่งฟรีเป็น 1000 ลองซื้อ 3 ตัวและ 4 ตัว

**ตรวจคำตอบ** กติกาแรกจ่าย 750 บาท กติกาใหม่จ่าย 800 และ 1000 บาทตามลำดับ

## บทที่ 3 · รวมตะกร้าด้วย slice และ for

[]int เก็บยอดหลายรายการตามลำดับ range คืนตำแหน่งกับค่าทีละรอบ ใช้ _ เมื่อข้ามตำแหน่ง ตั้ง subtotal ก่อนเข้าลูปเพื่อให้ยอดสะสมข้ามรอบได้

```powershell
go run ./03-loops
```

[03-loops/main.go](03-loops/main.go)

**ลองทำ** เพิ่มกระเป๋าราคา 350 บาทใน slice โดยแก้เพียงบรรทัดเดียว

**ตรวจคำตอบ** ยอดสะสมเดิม 500 → 650 และจ่าย 700 บาท หลังเพิ่มกระเป๋าจ่าย 1000 บาท

## บทที่ 4 · แยกกติกาเป็นฟังก์ชัน

subtotal int คือชื่อและชนิดของพารามิเตอร์ int หลังวงเล็บคือชนิดผลลัพธ์ เมื่อเจอ return ฟังก์ชันส่งค่ากลับให้ผู้เรียกทันที เงื่อนไข || ตรงเมื่ออย่างน้อยหนึ่งข้างเป็นจริง

```powershell
go run ./04-functions
```

[04-functions/main.go](04-functions/main.go)

**ลองทำ** เพิ่มกรณี 1 บาทและ 1001 บาท ทายค่าส่งก่อนรัน

**ตรวจคำตอบ** ค่าส่งของยอด 0, 999, 1000 คือ 0, 50, 0 บาท สองกรณีที่เพิ่มได้ 50 กับ 0

## บทที่ 5 · สร้างใบเสร็จด้วย struct และ map

struct รวมชื่อ ราคา และจำนวนไว้ในสินค้าหนึ่งรายการ ใช้จุดเลือกช่องข้อมูล map[string]int จับคู่ชื่อสินค้ากับจำนวนชิ้นรวม เมื่อยังไม่มีชื่อนั้น การอ่านค่าจำนวนเต็มจะได้ศูนย์ จึงบวกสะสมด้วย += ได้

```powershell
go run ./05-items
```

[05-items/main.go](05-items/main.go)

**ลองทำ** เพิ่มถุงเท้า 3 คู่ คู่ละ 120 และลองเพิ่มเสื้ออีกหนึ่งรายการเพื่อตรวจการรวมชื่อซ้ำ

**ตรวจคำตอบ** หลังเพิ่มเฉพาะถุงเท้า ยอดสินค้า 1010 บาท เมื่อเพิ่มเสื้ออีก 1 ตัว จำนวนเสื้อรวมเป็น 3

## บทที่ 6 · รับจำนวนสินค้าจากผู้ใช้และจัดการ error

fmt.Scan อ่านจากเทอร์มินัล &quantity ส่งตำแหน่งให้ Scan เขียนผลกลับมา ตรวจ err ก่อนใช้ quantity จากนั้นตรวจเงื่อนไขทางธุรกิจแยกอีกครั้ง เพราะจำนวนลบยังเป็นจำนวนเต็มที่อ่านได้

```powershell
go run ./06-input
```

[06-input/main.go](06-input/main.go)

**ลองทำ** รันใหม่สามครั้ง ป้อน 3, abc และ 0 แล้วสังเกตว่าแต่ละกรณีออกจากฟังก์ชันตรงไหน

**ตรวจคำตอบ** ได้ยอด 750 บาท ข้อความขอจำนวนเต็ม และข้อความช่วงจำนวน ตามลำดับ

## บทที่ 7 · จัดโปรเจกต์ด้วย module และบันทึก JSON

go.mod กำหนดราก module แต่ละโฟลเดอร์บทเรียนเป็น package main ที่รันแยกได้ json.Marshal แปลงข้อมูลเป็นไบต์ จากนั้น os.WriteFile บันทึกลงดิสก์ โหมด read อ่านไฟล์เดิมจากโฟลเดอร์ที่เปิดเทอร์มินัลแล้วถอด JSON กลับเป็น struct ชื่อช่องต้องขึ้นต้นด้วยตัวใหญ่เพื่อให้ encoding/json เข้าถึงได้

```powershell
go run ./07-files
```

[07-files/main.go](07-files/main.go)

**ลองทำ** รันโหมดเขียนหนึ่งครั้งแล้วรันคำสั่งเดิมต่อท้ายด้วย read เปลี่ยน Quantity ในไฟล์ JSON เป็น 3 แล้วอ่านอีกครั้ง

**ตรวจคำตอบ** อ่านครั้งแรกได้ เสื้อ 2 ครั้งที่สองได้ เสื้อ 3 หากไฟล์หาย โหมดอ่านรายงานข้อผิดพลาด

## บทที่ 8 · ใช้ pointer, method และ interface เปลี่ยนที่เก็บข้อมูล

Store ระบุพฤติกรรม Save โดยผู้เรียกไม่ต้องรู้วิธีเก็บ Memory ใช้ receiver *Memory เพื่อแก้ slice ของตัวจริง ส่วน File มี method รูปแบบเดียวกัน จึงส่งให้ checkout ได้ทั้งคู่ interface ใน Go จับคู่จากชุด method โดยอัตโนมัติ

```powershell
go run ./08-interfaces
```

[08-interfaces/main.go](08-interfaces/main.go)

**ลองทำ** เปิด practice-latest.txt หลังรัน แล้วลองส่ง Memory{} แทน m ให้ checkout อ่านข้อผิดพลาดของ compiler ก่อนแก้กลับ

**ตรวจคำตอบ** ทั้งสองแบบเก็บ order-101 ไว้ แบบไฟล์เก็บรายการล่าสุด ส่วนค่า Memory ต้องส่ง pointer เพราะ Save ประกาศบน *Memory

## บทที่ 9 · ล็อกกติกาค่าส่งด้วย test และหาจุดผิด

go test ค้นไฟล์ที่ลงท้าย _test.go แล้วเรียกฟังก์ชัน Test ที่รับ *testing.T ตัวอย่างนี้ใช้ตาราง input กับ want เพื่อให้กรณีขอบอยู่ติดกัน สำหรับฝึก debugger เปิดบทนี้ใน VS Code ที่มี Go extension ตั้ง breakpoint ที่ if ใน main.go แล้วเลือก Debug Test เหนือ TestShipping ดู subtotal เมื่อเป็น 1000 และกด Step Over เพื่อดูว่าเข้ากิ่งไหน

```powershell
go test ./09-tests -v
```

[09-tests/main.go](09-tests/main.go) [09-tests/main_test.go](09-tests/main_test.go)

**ลองทำ** แก้ >= เป็น > แล้วรัน go test ./09-tests -v อ่านค่า got กับ want ก่อนแก้กลับ

**ตรวจคำตอบ** กรณี 1000 ต้องล้มด้วย got 50, want 0 เมื่อคืนเครื่องหมาย >= ทุกกรณีจะผ่าน

## บทที่ 10 · บันทึกออเดอร์และตัดสต็อกด้วย SQL transaction

เปิด store.go เพื่ออ่าน Place ตามลำดับ เริ่ม transaction แล้ว UPDATE โดยมีเงื่อนไข stock >= ? ถ้าไม่มีแถวเปลี่ยนแปลว่าสินค้าไม่พอ ถ้าผ่านจึง INSERT ออเดอร์แล้ว Commit ทั้งคู่ defer Rollback ช่วยยกเลิกเมื่อออกก่อน commit เครื่องหมาย ? ผูกค่าจาก Go กับ SQL ร้านทดลองมีเสื้อราคา 250 บาท เริ่มต้น 5 ตัว

```powershell
go run ./10-sql
```

[10-sql/main.go](10-sql/main.go) [shop/store.go](shop/store.go)

**ลองทำ** รันสามครั้งกับฐานใหม่ แล้วเปิดรายการออเดอร์ด้วย API บทถัดไป

**ตรวจคำตอบ** สองครั้งแรกได้ยอด 550 บาทต่อครั้ง ครั้งที่สามสต็อกไม่พอ จึงมีออเดอร์ที่บันทึกเพียงสองรายการ

## บทที่ 11 · สร้าง HTTP API สำหรับสั่งซื้อและดูออเดอร์

GET /orders อ่านรายการ ส่วน POST /orders รับ JSON ที่มี quantity เซิร์ฟเวอร์ตรวจจำนวนก่อนคำนวณเงินเอง ส่ง 201 เมื่อสร้างสำเร็จ 400 เมื่อข้อมูลผิด และ 409 เมื่อสต็อกไม่พอ Context จาก request ส่งต่อไปยัง SQL เพื่อให้ฐานข้อมูลหยุดงานได้เมื่อคำขอถูกยกเลิก

```powershell
go run ./11-api
```

[11-api/main.go](11-api/main.go)

**ลองทำ** เปิดเทอร์มินัลอีกหน้ารัน Invoke-RestMethod http://127.0.0.1:8080/orders -Method Post -ContentType application/json -Body '{"quantity":1}' แล้วเรียก URL เดิมโดยใช้ GET

**ตรวจคำตอบ** ฐานใหม่จะได้ id 1 และ total 300 ปิดแล้วเปิดเซิร์ฟเวอร์ใหม่จากโฟลเดอร์เดิม GET ยังพบรายการ

## บทที่ 12 · จำลองตรวจพัสดุพร้อมกันด้วย goroutine, channel และ context

go เริ่มฟังก์ชันใหม่ให้ทำงานพร้อมกับ main แต่ละงานแข่งระหว่างเวลาตอบกลับจำลองกับสัญญาณยกเลิกผ่าน select ช่อง results มีที่พอให้แต่ละงานส่งผลหนึ่งครั้ง main รับจนครบก่อนจบโปรแกรม ลำดับการตอบขึ้นกับเวลาของแต่ละงาน

```powershell
go run ./12-concurrency
```

[12-concurrency/main.go](12-concurrency/main.go)

**ลองทำ** เพิ่ม timeout เป็นหนึ่งวินาที แล้วลองลดเหลือหนึ่งมิลลิวินาที

**ตรวจคำตอบ** ปกติงานแรกตอบทัน งานที่สองถูกยกเลิก เมื่อเพิ่มเวลาทั้งคู่ตอบทัน เมื่อลดเวลาทั้งคู่จะถูกยกเลิกในการรันทั่วไป

## บทที่ 13 · เชื่อมหน้าเว็บ React / Next.js กับ Go API

เริ่ม Go API จากบท 11 ก่อน แล้วเปิดเทอร์มินัลใหม่ หน้า Page อ่านรายการจาก GET และ map เป็นแถวที่มี key ตามเลขออเดอร์ ฟอร์มส่งข้อมูลให้ buy ฝั่งเซิร์ฟเวอร์ ซึ่งแปลง quantity เป็นตัวเลขแล้ว POST ไปยัง Go เมื่อสำเร็จ revalidatePath ทำให้เห็นยอดใหม่ทันที ถ้า API ตอบ 409 หน้าจอจะแจ้งว่าสินค้าไม่พอ

```powershell
cd web
npm ci
npm run dev
```

[web/app/page.jsx](web/app/page.jsx)

**ลองทำ** เปิด http://127.0.0.1:3000 สั่ง 1 ตัว จากนั้นลองสั่ง 100 ตัวแล้วรีเฟรช

**ตรวจคำตอบ** ครั้งแรกได้ออเดอร์ใหม่เมื่อมีสต็อก ครั้งที่สองเห็นข้อความสินค้าไม่พอ และจำนวนออเดอร์คงเดิม

## บทที่ 14 · ทดสอบทั้งระบบและ build โปรแกรมส่งมอบ

go run สร้างโปรแกรมชั่วคราวแล้วรันทันที ส่วน go build -o กำหนดชื่อไฟล์โปรแกรมที่จะเก็บไว้ บน Windows ไฟล์ shop-api.exe เปิด API ได้เอง เปิดจากโฟลเดอร์เดิมทุกครั้งเพื่ออ่านฐานข้อมูลเดิม เมื่อต้องการทดลองด้วยฐานใหม่ให้เปิดจากโฟลเดอร์ทดลองว่าง

```powershell
go test ./...
go build -o shop-api.exe ./11-api
.\shop-api.exe
```



**ลองทำ** หยุดเซิร์ฟเวอร์เดิมด้วย Ctrl+C แล้วรันไฟล์ที่ build จากโฟลเดอร์ว่าง สั่งเสื้อ 4 ตัว จากนั้นสั่งอีก 2 ตัว ปิดแล้วเปิดใหม่และอ่านรายการอีกครั้ง

**ตรวจคำตอบ** คำขอแรกได้ 201 ยอด 1000 บาท คำขอที่สองได้ 409 หลังเปิดใหม่ยังมีออเดอร์แรกเพียงรายการเดียว
